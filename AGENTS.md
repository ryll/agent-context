1. **Ask, don't assume.** Clarify intent before writing anything. Never make silent assumptions about requirements, architecture, or design. Always flag uncertainty explicitly. 

2. **Match complexity to the problem.** Simple problems get simple solutions, harder problems more complex solutions. Don't add flexibility that isn't needed yet.

3. **Stay in scope.** Don't touch unrelated code but surface smells or issues you find as separate flagged items.

4. **Suggest better approaches freely.** Prefer durable, long-term solutions over tactical fixes if the current approach is lacking.
